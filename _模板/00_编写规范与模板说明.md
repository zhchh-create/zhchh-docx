# 全栈技术栈详解 · 统一编写规范与模板说明

> 本文件是全部 69 个技术点 HTML 文件的**唯一权威样式与内容规范**。
> 写作时必须同时参考两个种子文件（它们本身就是交付物，也是风格基准）：
> - `01_前端基础/01_HTML5与CSS3【深入】.html`（【深入】级基准）
> - `01_前端基础/06_浏览器原理与渲染机制【标准】.html`（【标准】级基准）
> 规范与本文件冲突时，以本文件为准；本文件未覆盖的细节，以种子文件的实际写法为准。

---

## 0. 总则

- 每个技术点一个自包含 HTML 文件：内联 CSS 与 JS，浏览器直接打开即可用；简体中文正文。
- 每个文件必须含 7 大板块（`sec1`~`sec7` 锚点），缺一不可。
- 深度标签与内容深度严格对应：`【深入】`＝原理+流程+源码级+面试+项目实战；`【标准】`＝概念+要点+用法；`【基础】`＝是什么+能做什么+入门要点。
- 所有文件视觉完全一致：复制本规范的 `<style>` 块，不得增删改样式类；标题层级、配色、字号、卡片、表格、代码块、图注全部统一。

## 1. 设计令牌（不要改动）

| 令牌 | 值 | 用途 |
|---|---|---|
| `--bg` | `#f4f6f9` | 页面底色（冷灰，非奶油色） |
| `--surface` | `#ffffff` | 卡片/内容面 |
| `--line` / `--line-2` | `#e2e8f0` / `#cbd5e1` | 边框/分隔 |
| `--ink` / `--ink-2` / `--ink-3` | `#1f2937` / `#475569` / `#6b7280` | 正文三级字色 |
| `--accent` | `#1d4ed8` | 主强调（蓝） |
| `--accent-2` | `#0e7490` | 次强调（青） |
| `--warn` / `--danger` / `--ok` | `#b45309` / `#b91c1c` / `#047857` | 警示/错误/正向 |
| 代码块 | 底 `#0f172a`、字 `#e2e8f0` | 深色代码区 |

- 深度徽章：`深入`＝红、`标准`＝蓝、`基础`＝绿（badge 类 `.deep/.std/.basic`）。
- 字体：正文 `-apple-system, "Segoe UI", "Microsoft YaHei", "PingFang SC", "Noto Sans SC", sans-serif`；代码 `"Cascadia Mono", "JetBrains Mono", Consolas, "Courier New", monospace`。**不引入任何外部字体**（离线可开）。
- 正文字号 15px、行高 1.75；h1 30px（移动端 23px）、h2 21px、h3 17px、h4 15px。
- 禁止 emoji；图标一律内联 SVG；每个文件必须有内联 SVG favicon（`data:image/svg+xml`）。

## 4. 规范 JS（必须原样复制到每个文件的 `</body>` 前）

```html
<script>
(function () {
  'use strict';
  try {
    var btn = document.getElementById('backTop');
    if (btn) {
      var toggle = function () { btn.classList.toggle('show', window.scrollY > 480); };
      window.addEventListener('scroll', toggle, { passive: true });
      toggle();
      btn.addEventListener('click', function () { window.scrollTo({ top: 0, behavior: 'smooth' }); });
    }
  } catch (e) {}
  try {
    var pres = document.querySelectorAll('pre.code');
    for (var i = 0; i < pres.length; i++) {
      (function (pre) {
        var b = document.createElement('button');
        b.type = 'button'; b.className = 'code-copy'; b.textContent = '复制';
        b.setAttribute('aria-label', '复制代码');
        pre.appendChild(b);
        b.addEventListener('click', function () {
          var codeEl = pre.querySelector('code');
          var text = codeEl ? codeEl.innerText : pre.innerText;
          var done = function () { b.textContent = '已复制'; setTimeout(function () { b.textContent = '复制'; }, 1600); };
          function fb(t, ok) {
            try {
              var ta = document.createElement('textarea');
              ta.value = t; ta.style.position = 'fixed'; ta.style.opacity = '0';
              document.body.appendChild(ta); ta.select();
              document.execCommand('copy'); document.body.removeChild(ta); ok();
            } catch (e2) {}
          }
          if (navigator.clipboard && navigator.clipboard.writeText) {
            navigator.clipboard.writeText(text).then(done, function () { fb(text, done); });
          } else { fb(text, done); }
        });
      })(pres[i]);
    }
  } catch (e) {}
})();
</script>
```

## 5. 图示规范（图文并茂的硬性要求）

1. **数量**（用户已确认）：【深入】2-3 张图（必须含原理/流程类图）；【标准】1-2 张（必须含 1 张原理图）；【基础】1 张（结构图或流程图均可）。
2. **形式**：一律**内联 SVG**（离线可渲染、初始可读、失败不空白）。仅当确有"精确数值型"数据（性能基准、对比数字等）时可额外用 ECharts，且必须满足：jsDelivr CDN（`https://cdn.jsdelivr.net/npm/echarts@5.4.3/dist/echarts.min.js`）、`if (window.echarts)` 守卫、容器有 `min-height`、`resize` 监听。**每个文件无论是否用 ECharts，都必须有 ≥1 张内联 SVG 图兜底。**
3. **SVG 画布约定**：`viewBox="0 0 800 {H}"`，`width="100%"`，`height="auto"`，`role="img"` + `aria-label`。节点用圆角矩形、连线用 `marker-end` 箭头；节点内文字 13-15px，`text-anchor` 按位置选择；节点间距宁大勿小，禁止文字重叠；颜色只作辅助区分时，必须同时用文字/形状/线型/图例表达。
4. **箭头定义**（每个文件定义一次）：`<defs><marker id="arr" markerWidth="10" markerHeight="10" refX="8" refY="3" orient="auto"><path d="M0,0 L8,3 L0,6 Z" fill="#64748b"/></marker></defs>`，连线用 `stroke="#64748b" marker-end="url(#arr)"`。
5. **配色**：线 `#94a3b8`、节点填充 `#eff6ff`/`#ecfeff`、主强调描边 `#2563eb`、次强调 `#0d9488`、警示 `#d97706`、危险 `#dc2626`、文字 `#334155`；可加浅色底区分分区（如 `#f1f5f9` 泳道背景）。
6. **图注**：统一格式 `图 N 标题`（N 为该文件内从 1 递增），示意性结构必须标注"（示意）"；引用真实数据时注明来源。SVG 外层的 `<div class="diagram">` 包住，图注用 `.diagram-caption`。
7. 禁止地图、禁止任何形式的"图裂/空白"降级。

## 6. 七大板块内容规范（用户确认的金标准，逐板块执行）

### 板块 1 技术点概览
- 是什么（定义，含英文原名与版本定位）→ 解决什么问题（痛点→价值）→ 在本技术栈/简历项目里的定位。
- **必须配 1 张定位/结构图**（如：在渲染链/分层架构/数据流中的位置）。
- 【深入】级还必须做**横向对比**（如 ECharts vs Chart.js/D3/AntV、HTML5 vs 传统方案、Webpack vs Vite 等），讲清取舍依据而非罗列差异。

### 板块 2 核心概念
- 分条列出，每条＝**概念名（英文原名）+ 3-6 句实质说明 + 为什么重要/典型场景**，禁止一句话带过。
- 数量：【深入】8 条左右、【标准】4-5 条、【基础】3-4 条。
- 概念要覆盖该技术点的**核心心智模型**（例：ECharts 的 option 配置对象、坐标系、系列类型、dataset、交互组件、事件联动、主题扩展）。

### 板块 3 工作原理/流程
- 用流程图/架构图/时序图讲透原理，**每张图下方配 3-6 步文字讲解**（每步有实质内容）。
- 数量：见第 5 节；【深入】要求包含 2-3 张，覆盖"渲染管线/机制图、增量更新或 merge 机制图、大数据或高频场景原理图"这类层次的图。
- 讲 Why：为什么这样设计、瓶颈在哪、机制间如何衔接。

### 板块 4 核心语法/API 要点
- 分条例出常用语法、API、配置，**每条附关键代码片段**（短小、可运行或可读）。
- 【深入】必须出现"两种写法对比"式讲解（例：`setOption` 局部更新 vs `appendData` 增量、同步 vs 异步、全量 vs 差异）。
- 代码块用 `<pre class="code" data-lang="…"><code>…</code></pre>`，HTML 特殊字符（`<` `>` `&`）必须转义。
- 代码里的关键行可用注释说明"为什么"。

### 板块 5 使用案例（真实项目落地）
- 数量：【深入】2 个、【标准】1 个、【基础】1 个（可简短）。
- 每个案例**四段式**：`业务场景`（哪个项目、什么业务）→ `落地步骤`（怎么接入/配置，分步）→ `关键代码`（真实感代码片段）→ `效果与坑`（量化效果 + **具体真实的坑**，如"全量 setOption 导致卡顿→改 merge 局部更新 + large 模式"）。
- 案例必须就近取材于"简历事实库"（第 8 节），禁止编造项目；简历未覆盖的技术（如 GoJS、Oracle），案例要诚实写为"选型评估/通用实践"，不得虚构履历事实。
- 效果描述尽量给数字（帧率、秒、内存、耗时），示例性数字标注"（示意）"。

### 板块 6 易错点/面试重点
- 数量：【深入】5-6 条、【标准】4-5 条、【基础】3-4 条。
- 每条＝真实踩坑或高频考点：现象 → 原因（原理级） → 正解。禁止一句带过。

### 板块 7 学习资源/参考
- 官方文档优先（MDN、官网、GitHub 仓库、规范站点），附 1-2 本经典书籍/权威文章。
- **链接必须是真实存在的权威域名**，禁止编造 URL；不确定就只写官网根域名。
- 按"官方文档 → 书籍/课程 → 实战文章"分组列出。

## 7. 内容红线（用户反复强调，违反即返工）

1. **禁止模板化套话**：不以"随着…的发展"开头；不用"X 非常强大/十分常用/易于上手"这类无信息量表述；不同文件之间禁止复制段落或句式；同一文件内禁止重复表述。每句话都要携带具体信息（版本号、机制名、数值、对比、因果）。
