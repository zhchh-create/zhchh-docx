代码评审与协作流程

标准 定位：协作交付——分支策略 / PR / 检查清单 / AI 辅助评审

代码评审（Code Review）是团队保证质量、共享知识的核心环节。它不只是"挑错"，而是通过分支与 PR/MR、明确检查清单、聚焦关键问题，让变更可控可追溯。本页讲分支策略、PR 流程、评审关注点与 AI 辅助评审的落地。

1技术点概览

是什么

一句话定位：合入主干前，由同伴审查变更——兼顾质量与知识共享。

  • 流程：分支隔离改动 → 提 PR/MR → 自动检查 + 人工评审 → 合并。

解决什么问题

一句话定位：让每个变更都被看过、被记录、可回滚。

  • 痛点：直接往主干提交会引入未审过的改动，问题难追溯。

2核心概念

2.1 分支策略

一句话定位：主干保护，短分支小步提交。

  • 做法：开发在 feature 分支，通过 PR 合入；避免长生命周期大分支。
  • 常见分支模型：GitHub Flow（主干 + 短 feature 分支、随时可发布）、Trunk-Based Development（短分支频繁合主干、配特性开关）、Git Flow（release/hotfix 分支、适合周期性发版）；小团队常用前两者。
  • 合并策略：merge 保留完整分支历史、squash 把多条提交压成一条以保持主干干净、rebase 得到线性历史；受保护分支配合"必需 reviewer + CI 必过"作为合入门禁。

图 2 三种分支模型对比（示意）

2.2 PR / MR

一句话定位：PR 是评审载体——描述改动、关联需求、触发 CI、留记录。

  • 要素：改动说明、需求关联、CI 状态、评审记录。

2.3 检查清单（Checklist）

一句话定位：把"该查什么"固化成清单，评审不凭感觉。

  • 清单项：是否改了不该改的、边界条件、错误处理、测试。

2.4 评审关注点

一句话定位：人管逻辑，机器管风格。

  • 人看：设计是否合理、边界与异常、可读性、是否埋坑。
  • 交给 lint：风格与格式。

2.5 AI 辅助评审

一句话定位：AI 先扫 diff 找潜在问题，人工复核，提高覆盖面。

  • 定位：辅助而非替代人工——AI 找明显问题（未处理边界、命名不规范、潜在 bug），人做最终判断。
  • 用法：把 PR 的 diff 和描述丢给 AI（Cursor/ChatGPT），让它按检查清单逐项过；把 AI 输出作为评审参考，不直接采纳。

图 4 AI 辅助评审流程（示意）

2.6 评审反馈的写法

一句话定位：反馈要具体、可执行、对事不对人。

  • 写法：指出"这里边界情况会怎样"而非"你写错了"。
  • 分级：区分阻塞项（必须改）与建议项（可后续优化）。
  • 坑大段重写建议不如给一两个指向，避免评审变成代笔。

3工作原理与流程

3.1 分工原则

机器管机械项（lint、格式、单测），人管设计与逻辑。评审者别在空格风格上消耗精力，聚焦"这段改动会不会出问题、好不好维护"。

4核心做法要点

4.1 评审检查清单

□ 是否只做本需求的改动（无夹带）
□ 边界/空值/异常分支是否处理
□ 命名与可读性是否达标
□ 是否有测试、是否跑过
□ 安全与权限是否被破坏

5实战项目经验（实战落地）

5.1 项目背景（业务量级/场景）

一句话定位：团队 feature 分支开发，需 PR 门禁与 CI 保障合并质量。

  • 场景：多开发者并行，合并前需自动校验+人工评审。

5.2 我的角色与职责

一句话定位：开发者，既是 PR 作者也是评审人。

  • 分工：提 PR、回应评审意见、评审他人 PR。

5.3 技术栈/工具

  • 流程：feature 分支 + PR + CI（lint/构建/测试）。

5.4 落地设计（关键做法）

一句话定位：CI 绿了再人工评审，意见分级。

  • 触发 CI：lint + 构建 + 测试，绿了再人工评审。
  • 意见分级：按"必须改/建议改"分级，作者改完再评。

5.5 关键实现要点

  • 要点AI 先扫 diff 给初筛，人工复核结论。

5.6 真实问题与解法

  • 坑PR 过大：难以评审——拆分小 PR。
  • 坑意见口水战：以检查清单与分级收敛讨论。

5.7 量化成果

  • 质量：合并前自动门禁拦截低级问题。

5.8 协作与排期过程

  • 契约先行：团队评审检查清单对齐后统一执行。

5.9 复盘与可复用经验

  • 要点小 PR 好评审。
  • 要点AI 初筛+人工复核。

5.10 面试讲法

抓手「团队用 feature 分支+PR+CI（lint/构建/测试）门禁，意见按必须改/建议改分级，AI 先扫 diff 初筛再人工复核。」

6易错点与面试重点

6.1 评审只看风格

要点正解：风格交给 lint，人看设计与边界。

6.2 大 PR 难评审

坑正解：拆小、分步提。

6.3 评审变成挑错会

坑正解：对事不对人，目标是质量而非问责。

6.4 AI 评审结论照单全收

坑正解：AI 初筛，人工复核。
