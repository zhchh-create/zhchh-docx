1技术点概览

是什么

HTML5 是超文本标记语言的第五版规范，目前由 WHATWG 以 Living Standard（活标准，持续更新，不再按版本号发布）形式维护，2019 年 W3C 与 WHATWG 签署合作备忘录后也停止独立发布 HTML 规范，以 Living Standard 为唯一现行版本。相比 HTML4/XHTML，它新增了语义化标签（header/nav/main/section/article/aside/footer）、多媒体（video/audio）、图形（canvas、内联 SVG）、表单增强（新 input 类型与约束校验）、浏览器 API（Web Storage、History、Geolocation、WebSocket、Web Worker 等）。CSS3 则不是"第三个版本"，而是 CSS 的模块化演进：每个能力独立成模块并单独定级——Selectors、Flexbox（CSS Box Alignment Module Level 3）、Grid（CSS Grid Layout Module Level 1）、Transforms、Animations、Media Queries 各自成熟发布，浏览器按模块渐进支持。

解决什么问题

2010 年代前的 Web 开发有三座大山：table 布局与"div 海洋"让结构与表现混杂、改版成本极高；Flash 垄断多媒体，在 iOS 上不可用且安全漏洞频发；布局、动画全靠 JS hack（float 清除、定时器做动画、JS 量测做自适应），代码脆弱且无法利用 GPU 合成。HTML5 用语义让爬虫、无障碍工具和框架都能读懂页面结构；CSS3 用原生 Flex/Grid、过渡动画、媒体查询把这些 JS 活接回浏览器引擎，配合 GPU 合成线程大幅提升流畅度。

横向对比：为什么不是旧方案

  • HTML5 语义化 vs HTML4 的 table/div 布局：table 布局渲染时要等整表尺寸确定才出结果（首屏慢），且改一列牵全身；div 海洋让文档大纲完全失真。语义化换来的是可维护性（结构即文档）、SEO 结构化数据、无障碍（读屏器按 landmark 导航），代价是迁移成本——这正是"HTML5 迁移"曾是专门项目的原因。
  • CSS3 模块 vs CSS2.1：CSS2.1 时代实现"三栏布局 + 圆角 + 渐变"分别靠 float hack、切图、滤镜滤镜，都是不可维护的 workaround。CSS3 用 Flexbox（一维）与 Grid（二维）原生接管布局，用 border-radius/box-shadow/gradient 干掉切图，用 transition/animation 干掉 JS 定时器动画；代价是浏览器支持差异需要降级策略（详见板块 6）。
  • 原生 CSS vs 框架方案（Tailwind/组件库/预处理器）：原子化 CSS 与组件库解决"团队一致性与迭代速度"，代价是构建链依赖、产物体积、以及换肤时样式源分散。本套技术栈（大屏/管理平台）的取舍是"组件库（ElementUI/ElementPlus）+ CSS 变量主题 + 少量 SCSS"，理由是长期维护的组件生态与夜间大屏换肤需求（见板块 5 案例 2）。

2核心概念

2.1 语义化标签与文档大纲（Semantic HTML & Document Outline）

一句话定位：语义化不是性能优化，而是让"结构本身携带含义"——选择标签依据内容是什么，而非它长什么样。

  • 结构即信息：header/nav/main/section/article/aside/footer 让浏览器生成文档大纲、爬虫理解主题、读屏器提供"跳转区域"导航。
  • 怎么选：可单独分发的独立内容用 <article>，做主题分组用 <section>，与主内容松散相关的补充用 <aside>。

要点目的是让文档在失去 CSS 后仍然是"一篇有结构的文章"。

2.2 盒模型（Box Model）与 box-sizing

一句话定位：元素是 content→padding→border→margin 四层矩形；box-sizing 决定 width 到底含不含 padding/border。

  • 标准盒模型（W3C）：width 只算 content。
  • border-box（怪异盒）：width 含 content+padding+border——旧 IE 默认。
  • 差异：给元素设 100% 宽再加 padding/border，两种模型差出整整两倍 padding+border。

工程惯例全局 *{box-sizing:border-box} reset，让"宽度即占位宽度"成立，栅格/百分比布局不再手工减 padding。

2.3 块级格式化上下文（BFC, Block Formatting Context）

一句话定位：BFC 是布局引擎划出的"独立渲染领地"，内部布局不与外部互相渗透。

  • 触发条件：position:absolute/fixed、非 none 的 float、非 visible 的 overflow、display:inline-block/flow-root，以及 flex/grid 容器的直接子项（flex item / grid item，其自身非 flex/grid/table 容器）等。注：display:flex/grid 容器本身建立的是 FFC/GFC，并非 BFC。
  • 解决三类问题：子元素 margin 溢出父盒、浮动元素盖住兄弟内容、父盒不包裹浮动子元素（高度塌陷）。

最优雅触发display:flow-root——不改变盒类型，只产生格式化上下文，无副作用。

2.4 层叠上下文与 z-index（Stacking Context）

一句话定位：z-index 不是全局数值，只在同一个层叠上下文内部才可比较。

  • 触发面很广：除 position+z-index 外，opacity<1、transform/filter/will-change、mix-blend-mode、contain:paint 都会凭空造出一个上下文。
  • 玄学 bug：加 transform:translateZ(0) 触发 GPU 合成后，元素 z-index 只在"自己的小世界"里生效，数值更大却盖不过兄弟——它被困在父级创建的上下文里。

坑排查"z-index 不生效"的唯一正确路径，就是沿父级一层层找谁创建了层叠上下文。

2.5 选择器与特殊性（Specificity）

一句话定位：特殊性按四元组计分，避免把它堆得太高，否则最终只能靠 !important 续命。

  • 四元组：(内联样式, id 数, 类/属性/伪类数, 元素/伪元素数)，如 0,1,0,0；内联 > id > 类 > 元素。
  • 三个新选择器：:where() 特殊性恒为 0（写 reset 不污染后续覆盖）；:is() 取参数里最高的那个；:has() 父选择器（2023 年起主流浏览器均支持），如 a:has(> img)、.card:has(.active)，按子元素状态反向选父级。

坑#nav .item a.active 这类高特殊性选择器会让后面的样式越来越难覆盖，滥用 !important 让样式表失去可预测性。

2.6 层叠规则（The Cascade）

一句话定位：同一属性多处声明，按"来源 → 特殊性 → 出现顺序"三步裁决。

  1. 来源与重要性：浏览器默认 < 用户 < 作者；!important 会把整档反转。
  2. 特殊性：来源相同则比四元组。
  3. 出现顺序：后声明的覆盖先声明的。

要点这解释了"reset 放最前、覆盖样式最后"的惯例，也解释了 @layer（级联层）为何成为新规范——把来源这一维扩展成作者内部可控的显式分层。

2.7 Flex 弹性布局（一维布局）

一句话定位：在一根轴上分配空间与对齐；先按 flex-basis 排好，再用 grow/shrink 消化剩余。

  • 容器属性：flex-direction 定主轴、justify-content 管主轴分配、align-items 管交叉轴对齐、gap 管间距。
  • 项目属性：flex-grow/flex-shrink/flex-basis 决定剩余空间怎么分、不足时怎么缩。

要点它是 float 的全面替代（不用清浮动、能垂直居中、能换行）；局限是只处理一维——同时约束行与列就力不从心。

2.8 Grid 网格布局（二维布局）

一句话定位：把容器划成显式轨道与命名区域，同时约束行与列，是"页面骨架"级布局的正解。

  • 核心概念：grid-template-columns/rows 定轨道、grid-template-areas 命名区域；放不下的进隐式网格（grid-auto-rows）。
  • 新单位：fr 比例分配剩余空间（区别于百分比）、minmax() 定轨道弹性范围。

要点Flex 管"一行内的排列"，Grid 管"整页行列结构"；Grid 的一格内部常再嵌一个 Flex——两者是互补而非竞争。

2.9 单位体系：px/em/rem/vw/vh 与 calc()/clamp()

一句话定位：rem 是全局缩放的正解，vw/vh 只用于页面级尺寸，calc/clamp 做计算与弹性区间。

  • 各单位：px 绝对；em 相对当前字号（padding/margin 上会连锁放大，慎用）；rem 相对根字号；vw/vh 相对视口；% 相对包含块。
  • 三原则：根字号驱动 rem（按设计稿整体缩放）；视口单位只用于页面级尺寸；clamp(14px,2vw,18px) 让字号在区间内随视口平滑变化。

坑100vh 在移动端包含地址栏区域，页面底部被遮挡。

2.10 过渡、变换与动画：性能的三原则

一句话定位：只动 transform 与 opacity，因为它们走合成线程、不触发重排重绘。

  • 可插值性：width/height 可插值但触发重排；opacity/transform 不触发。
  • 三原则：只动 transform 与 opacity；动画元素必要时提升为独立图层（will-change，别滥用）；尊重 prefers-reduced-motion。

动画的价值是"状态变化的引导"，为动画而动画会拖慢页面并消耗移动端电量。

3工作原理与流程

3.1 渲染流水线：HTML/CSS 如何变成像素

理解这条链路是理解前端性能优化的地基。浏览器拿到 HTML 字节后，先在渲染进程的主线程上走完解析与样式计算，再交给合成与光栅化（部分阶段可并行/异步）。每一步的输入输出如下：

图 2 渲染流水线：从字节到像素的五个阶段（示意）

  1. 解析（Parse）：HTML 按"字节→字符→Token→Node"四步变成 DOM 树；CSS 同样变成 CSSOM。注意 CSS 规则匹配是自右向左的（先找右端选择器命中的元素再回溯验证祖先），所以 .nav .item 比 .nav div.item 快——右端越具体，命中集越小。
  2. 样式计算（Style）：对每个 DOM 节点执行层叠裁决，产出计算样式（computed style）。样式计算与 DOM 构建可交错进行（遇到 <link> 会阻塞渲染直至 CSSOM 就绪——这就是为什么 CSS 是"渲染阻塞资源"）。
  3. 布局（Layout）：按盒模型、BFC、Flex/Grid 算法算出每个盒的几何（位置与尺寸）。布局结果是"布局树"（Layout Tree），只含可见节点；display:none 的节点不进树。
  4. 绘制（Paint）：把每个盒的可见样式转成绘制指令序列（先背景、再边框、再内容、再定位元素，顺序由层叠上下文决定）。
  5. 合成（Composite）：主线程把页面按层（layer）切分，合成线程按帧把各层光栅化后的位图拼到屏幕上。合成只发生在合成线程，不占用主线程——这就是 transform/opacity 动画流畅的根源。

3.2 层叠裁决：一条属性到底听谁的

图 3 层叠裁决三步流程（示意）

  1. 收集：找出所有匹配该元素的声明（含继承、含 @layer 内外的层）。继承不是层叠的一部分：可继承属性（如 color/font）在"无任何声明"时从父元素取计算值。
  2. 来源与重要性：作者样式默认压过浏览器默认样式，这是 reset 类样式能"清零"默认外观的前提。!important 是来源维上的反转，工程上应只在覆盖第三方样式等极端场景使用。
  3. 特殊性与顺序：同来源内先比特殊性，再比声明顺序。这意味着"把覆盖样式写在后头"是合理惯例，也意味着组件库的样式通常特意保持在较低特殊性，方便业务覆盖。

3.3 Flex 与 Grid 的布局算法：一维与二维的分工

图 4 Flex 与 Grid：一维 vs 二维的分工（示意）

Flex 的尺寸决议顺序是：先按 flex-basis（默认 content 尺寸）排布，再用 flex-grow 把剩余空间按比例分给允许增长的项、用 flex-shrink 在空间不足时按比例压缩。Grid 的轨道决议是两轮的：第一轮按内容的 max-content 估算各轨道最小/理想尺寸，第二轮把剩余空间按 fr 权重分配。这就是为什么"Flex 容器内一列内容特别宽会挤压兄弟列"，而 Grid 用 1fr 1fr 能强制两列等宽（fr 是"空间单位"而非内容单位）。选型判断：工具栏、导航、列表项、居中场景用 Flex；仪表盘骨架、卡片栅格、需要区域命名的复杂版面用 Grid。

4核心语法与 API 要点

4.1 语义化文档骨架

<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>页面主题</title>
</head>
<body>
  <header>站点头部（logo、导航）</header>
  <main>
    <section>主题分组</section>
    <article>可独立分发的内容</article>
  </main>
  <aside>侧栏补充信息</aside>
  <footer>版权、链接</footer>
</body>
</html>

要点：main 一个页面只出现一次；h1 是文档主标题不是视觉元素；lang 属性直接影响读屏器发音与排版引擎的断词规则。

4.2 现代 reset 与盒模型

*, *::before, *::after { box-sizing: border-box; }
body { margin: 0; }               /* 浏览器默认 margin 清零 */
img, video { display: block; max-width: 100%; }
ul[class], ol[class] { list-style: none; padding: 0; }

4.3 Flex：最常用的三个模式

.center { display: flex; align-items: center; justify-content: center; }   /* 水平垂直居中 */
.nav { display: flex; gap: 12px; }                                          /* 间距用 gap，不写 margin hack */
.split { display: flex; }
.split > :first-child { flex: 1 1 0; }      /* 剩余空间全给第一项 */
.split > :last-child { flex: 0 0 auto; }    /* 末项保持内容宽 */

4.4 Grid：经典后台骨架

.layout {
  display: grid;
  grid-template-columns: 220px 1fr;              /* 侧栏固定，主区弹性 */
  grid-template-rows: 56px 1fr auto;
  grid-template-areas:
    "header header"
    "sidebar main"
    "footer footer";
  height: 100vh;
}
.header { grid-area: header; }
.sidebar { grid-area: sidebar; }
.main { grid-area: main; min-width: 0; }        /* min-width:0 防内容撑爆轨道 */

高频坑提醒：Grid 项目默认 min-width:auto，长内容（如超长英文串、表格）会把轨道撑爆，显式 min-width:0 是标准解法。

4.5 自定义属性与 clamp

:root { --brand: #1d4ed8; --space: 16px; }
.button { background: var(--brand); padding: calc(var(--space) / 2) var(--space); }
.title { font-size: clamp(14px, 2vw, 18px); }  /* 视口越大字越大，卡在区间内 */

自定义属性在运行时可用 JS 改（el.style.setProperty('--brand', '#0e7490')），是"换肤"最轻量的实现（见案例 2）。

4.6 过渡、变换与动画

.card { transition: transform .25s ease, box-shadow .25s ease; }
.card:hover { transform: translateY(-4px); box-shadow: 0 8px 24px rgba(0,0,0,.15); }
@keyframes pulse {
  0%, 100% { opacity: 1; }
  50% { opacity: .55; }
}
.alarm { animation: pulse 2s ease-in-out infinite; }   /* 告警闪烁：只动 opacity */
@media (prefers-reduced-motion: reduce) {
  .alarm { animation: none; }
}

4.7 响应式：移动优先断点

/* 移动优先：基础样式面向窄屏，用 min-width 逐级增强 */
.grid { display: grid; grid-template-columns: 1fr; gap: 12px; }
@media (min-width: 768px) { .grid { grid-template-columns: repeat(2, 1fr); } }
@media (min-width: 1200px) { .grid { grid-template-columns: repeat(4, 1fr); } }
/* 容器查询：按容器宽度而非视口适配（2023 年后主流浏览器均支持） */
.panel { container-type: inline-size; }
@container (min-width: 400px) { .panel > .body { grid-template-columns: 1fr 1fr; } }

4.8 表单增强：类型与约束校验

<form>
  <input type="email" name="mail" required
         pattern="[^@]+@[^@]+\.[^@]+" placeholder="name@example.com">
  <input type="tel" name="phone">
  <input type="date" name="date">
  <input type="range" min="0" max="100">
</form>
input:invalid { border-color: var(--danger); }          /* 约束校验自动匹配伪类 */
input:valid { border-color: var(--ok); }

原生校验（Constraint Validation API）在提交时自动拦截并提示，服务端仍需二次校验——前端校验只是体验，不是安全边界。

5实战项目经验（实战落地）

5.1 项目背景

一句话定位：电力大屏可视化项目系列（2016-2022）智能监控大屏 智能监控——摄像头画面、光跟踪算法结果、告警信息聚合到大屏，且现场分辨率极其混杂。

  • 业务场景：调度/值班中心多屏轮播，光跟踪框必须与画面目标像素级对齐，否则值班员不信任结果。
  • 硬件碎片化：LED 拼接屏、多屏显示器、普通办公屏并存，物理分辨率 1366×768 ~ 4K 不等。

5.2 我的角色与职责

  • 角色：前端开发，负责大屏自适应缩放、跟踪叠加层定位、面板换肤与动画统一。
  • 团队与分工：前端 2-3 人、后端/算法若干（估算）；我负责大屏视觉层与适配方案。

5.3 技术栈

  • 布局：rem 等比缩放 + Flex 网格 + Grid 面板骨架 + CSS 变量主题。
  • 图表：ECharts 多面板轮播；叠加层用绝对定位 + 百分比。

5.4 落地设计

  • rem 一套样式等比缩放：设计稿 1920，脚本按 clientWidth/1920 设根字号并 clamp，全站尺寸 rem。
  • 叠加层百分比对齐：算法输出归一化坐标，叠层 left/top/width/height 全用百分比，随画面缩放自动对齐。
  • CSS 变量主题：白天/夜间两套 token，切换只改 data-theme。

5.5 关键实现要点

// 大屏 rem 缩放：设计稿 1920，根字号 1rem = 设计稿 1px 比例
function setRootFont() {
  var w = document.documentElement.clientWidth;
  var base = Math.min(100, Math.max(60, w / 19.2));   // 1920px → 100px
  document.documentElement.style.fontSize = base + 'px';
}
window.addEventListener('resize', setRootFont);

5.6 真实问题与解法

  • 旧内核降级：现场部分机器内核旧，rem 与 flex:1 简写解析差异，需降级写法。
  • transform 破层级：叠加层加 transition 平滑跟踪时，transform 新建层叠上下文致告警弹窗 z-index 失效——统一在叠加容器收敛层叠。
  • 小字发虚：1366 屏根字号约 71px，细汉字发虚；最小字号线提到 12px（rem 计算值）。
  • background 不能过渡：把 background 简写放进 transition 渐变生硬，拆成 background-color 才平滑。
  • ECharts 不随 CSS 换肤：canvas 不随主题自动变色，必须显式 setOption 同步，否则夜间图表仍白底。

5.7 量化成果

  • 1366×768 ~ 4K 全分辨率版面与跟踪框不失真，跟踪框与目标偏差视觉可接受（≤2px 级，估算）。
  • 夜间值班屏白色面积大幅下降（示意约 60%），换肤即时无闪烁。

5.8 协作与排期过程

  • 契约先行：与算法侧定归一化坐标协议 (x,y,w,h)，叠加层才敢用百分比定位。
  • 联调协商：ECharts 与页面换肤割裂问题，与图表开发约定"换肤时一起 setOption"。
  • 排期：先做 rem 缩放跑通 1920 基准，再补旧内核降级与夜间主题。

5.9 复盘与可复用经验

  • 一套样式等比缩放：rem + clamp 比为每种分辨率单独写媒体查询划算。
  • canvas 图表是 CSS 换肤盲区：凡 canvas 渲染的可视化都要手动同步主题。
  • 层叠上下文要统一收敛：transform/filter 会悄悄新建层叠，z-index 问题先查这个。

5.10 面试讲法

实战要点用 rem 等比缩放 + 百分比叠加层，在 1366~4K 混杂现场做到跟踪框像素级对齐，并用 CSS 变量统一了大屏日夜换肤。

6易错点与面试重点

6.1 盒模型手算题：border-box 到底差在哪

一句话定位：标准盒模型 width 只含 content，padding/border 额外累加会溢出。

  • 现象：div{width:100%;padding:20px;border:1px solid} 在标准盒模型下实际占位 100% + 42px，溢出父容器。
  • 正解：全局 *{box-sizing:border-box}。栅格系统必须 border-box。

6.2 margin 塌陷：为什么父元素的 margin 消失了

一句话定位：相邻块级垂直 margin 合并取最大值，且穿透未形成 BFC 的父盒。

  • 现象：父盒无 padding/border，子元素设 margin-top:20px，结果父盒整体下移、子 margin"穿透"。
  • 正解：给父盒触发 BFC（overflow:hidden 或更推荐 display:flow-root），或改用 padding/gap。

6.3 z-index 失效：加了 transform 之后层级乱了

一句话定位：transform/opacity/filter 创建新层叠上下文，z-index 只能在内部比。

  • 现象：弹窗 z-index:9999 依然被普通元素盖住。
  • 原因：弹窗或其祖先被 transform/opacity/filter/will-change 创建成新层叠上下文，弹窗"被困在小世界里"。
  • 正解：不要随便加 transform 触发合成层；置顶元素检查祖先链，必要时把 transform 移到兄弟元素上。

6.4 100vh 的移动端陷阱

一句话定位：vh 按最大视口算，比可见视口高，底部被地址栏遮。

  • 现象：height:100vh 底部在手机浏览器被地址栏遮住。
  • 正解：用 100dvh；兼容老浏览器用 100vh 兜底加 @supports 覆盖。

6.5 特殊性踩坑：nth-child 与 nth-of-type 记混

一句话定位：nth-child 按所有兄弟序号匹配，nth-of-type 才按同类型序号。

  • 现象：li:nth-child(2) 想选中第二个 li，却选中了别的东西。
  • 要点：:where() 特殊性为 0、:is() 取参数最高特殊性——特异性可控的伪类。

6.6 百分比高度失效

一句话定位：百分比高度要求父元素有确定高度，auto 父级给不了基准。

  • 现象：height:50% 无效，子元素高度塌为 0。
  • 正解：链条上显式给高度，或改用 flex/grid 拉伸（align-items 默认 stretch）。

6.7 img 底部多出一截空白

一句话定位：内联元素按基线对齐，图片底边留出下行部空间。

  • 现象：图片下方总有 4px 左右空隙。
  • 正解：img{display:block} 或 vertical-align:middle。
