  <h2><span class="num">5</span>使用案例（真实项目落地）</h2>
  <h3>案例：DCP-RMP 与源启——两套 Spring Boot 3 后端的搭建</h3>
  <p><strong>业务场景</strong>：两个后端项目都基于 Spring Boot 3 + Java 17。DCP-RMP（需求管理平台）要接 MySQL、Redis(Redisson)、Swagger/OpenAPI；源启（后端设计平台）要接 MyBatis + Redis。目标是：新人接手后一条命令起服务，环境差异靠 Profile 隔离。</p>
  <p><strong>落地步骤</strong>：</p>
  <ol>
    <li>引入 Starter：<code>spring-boot-starter-web</code>、<code>spring-boot-starter-data-redis</code>、<code>mybatis-spring-boot-starter</code>（源启）、<code>spring-boot-starter-validation</code>。</li>
    <li>配置文件分 <code>application-dev.yml</code>（本地 MySQL/Redis）与 <code>application-prod.yml</code>（容器内地址），统一参数用 <code>@ConfigurationProperties</code> 绑定。</li>
    <li>跨服务公共的 Web 增强（统一返回、全局异常、鉴权拦截器）抽成内部 starter，两个项目都引。</li>
    <li>用 <code>--spring.profiles.active=prod</code> 在容器启动时切换环境。</li>
  </ol>
<pre class="code" data-lang="java"><code>// 全局异常处理（内部 starter 里写一次，各服务复用）
@RestControllerAdvice
public class GlobalExceptionHandler {
    @ExceptionHandler(BizException.class)
    public Result&lt;Void&gt; onBiz(BizException e) {
        return Result.fail(e.getCode(), e.getMessage());
    }
}</code></pre>
  <p><strong>效果与坑</strong>：两个项目从空骨架到跑通 CRUD 基本零 XML，环境切换只靠 Profile。真实踩过的坑：</p>
  <ul>
    <li><span class="tag-pit">坑</span><strong>javax→jakarta</strong>：Boot 3 把 <code>javax.*</code> 全改成 <code>jakarta.*</code>，引了 Boot 2 时代旧 starter 报 <code>ClassNotFoundException: javax.servlet...</code>，必须换兼容 Boot 3 的版本。</li>
    <li><span class="tag-pit">坑</span><strong>主类放太深</strong>：<code>@ComponentScan</code> 默认只扫主类所在包及子包，另一个包里的 Bean 没被扫到——把主类放根包，或显式 <code>scanBasePackages</code>。</li>
    <li><span class="tag-pit">坑</span><strong>Redis 配置随环境漂移</strong>：本地配了 Redis 但容器里没配，自动配置仍去连本地 localhost；靠 Profile 把生产 Redis 地址配对才解决。</li>
  </ul>
