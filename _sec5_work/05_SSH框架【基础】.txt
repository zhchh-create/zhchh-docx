  <h2><span class="num">5</span>使用案例（真实项目落地）</h2>
  <h3>案例：早期项目对 SSH 的接触与后续演进（诚实说明）</h3>
  <p><strong>业务场景</strong>：本人早期在电力行业项目中接触过基于 Struts2 + Spring + Hibernate 的传统 Java Web 工程，用于内部管理后台。这是当时的主流技术栈；本简历中 DCP-RMP、源启等新项目已全面采用 Spring Boot 3 + MyBatis，SSH 仅作为历史技术背景与演进脉络了解。</p>
  <p><strong>落地步骤（当时做法）</strong>：</p>
  <ol>
    <li>用 Struts2 写 Action 接表单请求，配置 <code>struts.xml</code> 路由到 JSP。</li>
    <li>业务逻辑写在 Spring 管理的 Service 里，用 Hibernate 实体操作数据库。</li>
    <li>事务、数据源、视图解析器都在 Spring XML 里配置。</li>
  </ol>
  <p><strong>效果与坑</strong>：项目能跑，但维护成本随规模上升——改一个路由要翻 XML、Hibernate 自动生成的 SQL 偶尔拖慢页面。后来团队逐步迁到 SSM，再到今天的 Spring Boot。这个演进过程本身就是最大收获：理解了"为什么行业要从 XML 配置走向注解与自动装配、为什么持久层从全自动 ORM 转向可控 SQL"。</p>
</section>
