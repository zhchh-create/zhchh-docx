  <h2><span class="num">5</span>使用案例（真实项目落地）</h2>
  <div class="warn-box"><strong>诚实说明</strong>：本人简历项目（DCP-RMP、源启）均以 MySQL 为主，<strong>未在简历中列独立 Oracle 项目</strong>。以下案例为 Oracle 的经典场景，结合本人对这类企业级库的了解与接触经验整理，用于面试时展示"知道差异、能接手"，不虚构履历。</div>

  <h3>案例 1：经典场景——大型系统的主键与分页迁移</h3>
  <p><strong>场景（经典）</strong>：一个运行多年的 Oracle 核心系统，分页是老式两层 ROWNUM 写法，主键用 sequence。</p>
  <p><strong>落地步骤（典型做法）</strong>：</p>
  <ol>
    <li>主键统一由 sequence.NEXTVAL 提供，不依赖业务字段。</li>
    <li>新代码用 12c 的 OFFSET-FETCH 分页，老 ROWNUM 写法逐步替换。</li>
    <li>MyBatis 层用 databaseId 区分 Oracle/MySQL 分页方言。</li>
  </ol>
  <p><strong>经验与坑</strong>：接触这类系统时最容易踩的就是分页——</p>
  <ul>
    <li><span class="tag-pit">坑</span><strong>按 MySQL limit 思维写 Oracle 会报错</strong>：分页要用 ROWNUM/OFFSET-FETCH。</li>
    <li><span class="tag-pit">坑</span><strong>空字符串 '' 在 Oracle 等于 NULL</strong>：前端传空串做查询条件，和 MySQL 表现不同。</li>
  </ul>

  <h3>案例 2：经典场景——锁等待与 undo 排查</h3>
  <p><strong>场景（经典）</strong>：Oracle 系统偶发"业务卡住"，疑似锁等待。</p>
  <p><strong>排查思路（典型）</strong>：</p>
  <ol>
    <li>查 <code>V$SESSION</code> 找阻塞会话与被阻塞会话。</li>
    <li>查 <code>V$LOCK</code> 确认锁的对象与类型。</li>
    <li>找到未提交的长事务，结合业务缩短事务、统一加锁顺序。</li>
  </ol>
  <p><strong>经验与坑</strong>：</p>
  <ul>
    <li><span class="tag-pit">坑</span><strong>undo 表空间不监控会被长事务撑满</strong>：长事务/大量回滚撑满 undo 表空间导致写失败——这是 Oracle 特有运维点，MySQL 的 undo 管理相对透明。</li>
  </ul>
