  <h2><span class="num">5</span>使用案例（真实项目落地）</h2>

  <h3>案例 1：DCP-RMP 分层架构——用 IOC 装配 Controller/Service/Mapper</h3>
  <p><strong>业务场景</strong>：DCP-RMP（需求管理平台，Spring Boot 3 + Java 17）按 Controller → Service → Mapper 分层，需求增删改查、状态流转、事件发布等数十个 Bean。需要依赖关系清晰、可单测、能灵活替换实现。</p>
  <p><strong>落地步骤</strong>：</p>
  <ol>
    <li>所有 Service/Mapper 用 <code>@Service/@Mapper</code> 标注，Controller 只依赖 Service 接口类型，不 new 任何实现。</li>
    <li>统一用构造器注入 + <code>final</code>，依赖不可变；单测时直接 <code>new RequirementService(mockMapper)</code>，不需要启动 Spring 容器。</li>
    <li>公共能力（事件发布、当前用户上下文）抽成独立 Bean，各处注入复用，避免重复写工具类静态方法。</li>
  </ol>
<pre class="code" data-lang="java"><code>@RestController
@RequestMapping("/api/requirements")
public class RequirementController {
    private final RequirementService service;
    public RequirementController(RequirementService service) { this.service = service; }

    @PostMapping
    public Result&lt;Long&gt; create(@RequestBody @Valid ReqCreateDTO dto) {
        return Result.ok(service.create(dto));
    }
}</code></pre>
  <p><strong>效果与坑</strong>：依赖关系一目了然，单测从"起整个 Spring 容器"降到毫秒级。真实踩过的坑：</p>
  <ul>
    <li><span class="tag-pit">坑</span><strong>字段注入的 NPE 前移</strong>：早期图省事用 <code>@Autowired</code> 字段注入，单测忘注某依赖时运行期才 NPE；改成构造器注入后，这个问题前移到启动期就报错。</li>
    <li><span class="tag-pit">坑</span><strong>Bean 命名冲突</strong>：<code>@Service</code> 同名时后扫描的覆盖先扫描的，一度"改了实现却不生效"，靠 <code>@Qualifier</code> 显式指定解决。</li>
  </ul>

  <h3>案例 2：AOP 切面——统一日志、鉴权与 @Transactional 事务失效排查</h3>
  <p><strong>业务场景</strong>：DCP-RMP 里所有接口要统一记录耗时与操作人，写需求、流转状态这类多步操作要在一个事务里，权限要按角色校验。这些横切逻辑若散在每个方法里必然重复。</p>
  <p><strong>落地步骤</strong>：</p>
  <ol>
    <li>写一个 <code>@Aspect</code> 切 Controller 包，<code>@Around</code> 记录入参、耗时、异常，统一落日志。</li>
    <li>权限校验用注解 <code>@RequiresPermission("req:edit")</code>，切面读注解校验当前用户角色，不满足直接抛 403。</li>
    <li>状态流转、批量变更方法加 <code>@Transactional(rollbackFor = Exception.class)</code>。</li>
  </ol>
<pre class="code" data-lang="java"><code>@Around("@annotation(requiresPerm)")
public Object checkPerm(ProceedingJoinPoint pjp, RequiresPermission requiresPerm) throws Throwable {
    String need = requiresPerm.value();
    if (!currentUser().hasPermission(need)) {
        throw new BizException("FORBIDDEN", "需要权限: " + need);
    }
    return pjp.proceed();
}</code></pre>
  <p><strong>效果与坑</strong>：横切逻辑集中在两三个切面类，业务方法里没有一行日志/权限样板。真实踩过的坑（面试高频）：</p>
  <ul>
    <li><span class="tag-pit">坑</span><strong>自调用绕过事务</strong>：批量状态变更最初写成 <code>for(id){ this.changeStatus(id,next); }</code>，某条失败后前面已提交、没回滚——根因是 <code>this.</code> 自调用绕过了事务代理；改成注入自身代理 <code>self.changeStatus(...)</code> 后整个批量才在一个事务里。</li>
    <li><span class="tag-pit">坑</span><strong>private 方法上的 @Transactional 不生效</strong>：CGLIB/JDK 代理增强不到 private。</li>
    <li><span class="tag-pit">坑</span><strong>catch 住异常没 rethrow</strong>：事务以为成功而不回滚。</li>
  </ul>
