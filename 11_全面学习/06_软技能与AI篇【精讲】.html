代码设计原则

好代码不是能跑就行，是要易读、易改、易测试。SOLID 原则是经典指导。

  • 单一职责：一个类只做一件事
  • 开闭原则：对扩展开放，对修改关闭
  • 依赖倒置：依赖抽象，不依赖具体实现
  • 迪米特法则：最少知识，减少耦合
// 不好的写法：一个类管所有事
class OrderService {
  void createOrder() {}
  void sendEmail() {}
  void saveToDb() {}
}

// 好的写法：拆分职责
class OrderService {
  void createOrder() {}
}
class EmailService {
  void send() {}
}
class OrderRepository {
  void save() {}
}

调试技巧

调试是程序员的核心能力。不是只会 console.log，而是有系统地定位问题。

  • 二分法：注释一半代码，缩小范围
  • 看报错：先看错误堆栈，从最后一行往上找
  • 断点调试：用调试器一步步跑，看变量变化
  • 复现：先稳定复现，再谈修复
// 调试示例：打印关键变量
function processData(data) {
  console.log("输入数据:", data); // 先看输入对不对
  
  const result = step1(data);

  return step2(result);

AI 辅助编程

AI 编程工具不是替代你，是提升效率。会用 AI 的程序员，产能翻倍。

  • 代码补全：Copilot/Tabnine 自动补全重复代码
  • 代码解释：看不懂的代码丢给 AI 解释
  • 生成测试：让 AI 帮你写单元测试
  • 重构建议：AI 指出坏味道，给优化方案

团队协作与文档

代码是写给人看的，顺便能跑就行。好的文档和沟通，团队效率翻倍。

  • README：项目说明，新人 5 分钟看懂怎么跑起来
  • 注释：为什么这么做，而不是做了什么
  • PR 描述：改了什么、为什么改、怎么测的
  • 会议：少开会，开就有结论、有行动项
