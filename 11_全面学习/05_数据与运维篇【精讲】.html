2核心技术点精讲

MySQL 数据库

MySQL 是最常用的关系型数据库。核心是：表结构设计、索引优化、事务隔离级别。

  • 索引：B+ 树结构，加快查询，但会减慢写入
  • 事务：ACID 特性，四种隔离级别
  • 常见优化：explain 分析执行计划、避免全表扫描、避免索引失效
  • 范式：1NF/2NF/3NF，避免数据冗余
-- 创建表
CREATE TABLE user (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(50) NOT NULL,
  age INT,
  email VARCHAR(100),
  INDEX idx_name (name)
);

-- 查看执行计划
EXPLAIN SELECT * FROM user WHERE name = '张三';

Redis 缓存

Redis 是内存键值数据库，速度极快。常用于缓存、会话、排行榜、分布式锁。

  • 数据结构：String/Hash/List/Set/ZSet
  • 缓存穿透：布隆过滤器 / 空值缓存
  • 缓存击穿：热点 key 过期，加互斥锁
  • 缓存雪崩：大量 key 同时过期，加随机过期时间
# 基本操作
SET user:1:name "张三"
GET user:1:name

# 设过期时间
SET session:abc123 "user_info" EX 3600

# 排行榜（ZSet）
ZADD rank 100 "user1"
ZADD rank 95 "user2"
ZREVRANGE rank 0 9 WITHSCORES

Docker 容器化

Docker 把应用和依赖打包成容器，一次构建到处运行。解决环境不一致问题。

  • 镜像：只读模板，包含应用和运行环境
  • 容器：镜像的运行实例，互相隔离
  • Dockerfile：构建镜像的脚本
  • Docker Compose：多容器编排，一键启动
# Dockerfile 示例
FROM node:18-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
EXPOSE 3000
CMD ["npm", "run", "dev"]

# 构建运行
docker build -t my-app .
docker run -p 3000:3000 my-app

CI/CD 持续集成部署

CI/CD 让代码提交后自动构建、测试、部署。减少人工操作，快速发布。

  • CI（持续集成）：提交代码后自动跑测试
  • CD（持续部署）：测试通过后自动部署到环境
  • 常见工具：GitHub Actions、GitLab CI、Jenkins
  • 流程：push → 拉代码 → 安装依赖 → 测试 → 构建 → 部署
# .github/workflows/deploy.yml
name: Deploy
on:
  push:
    branches: [main]
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - run: npm install
      - run: npm run build
      - run: npm run test
      - name: Deploy to server
        run: echo "部署完成"

4常见误区与实战要点

常见误区：
  • MySQL 索引建了一堆，但查询还是慢，因为索引失效了
  • Redis 当数据库用，忘了持久化，重启数据全没了
  • 缓存穿透不处理，恶意请求直接打穿到数据库
  • Docker 镜像越做越大，构建部署都慢
