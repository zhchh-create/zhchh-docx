技术栈详解 · 09 DevOps 部署与运维

云原生与公有云部署

基础 定位：云主机 / 容器服务 / Serverless、对象存储与 CDN——与自建部署的对比与取舍

把应用部署到自己买的物理服务器上，叫自建；把服务器/运行环境租给云厂商，就是公有云。云原生则更进一步——应用天生按容器、弹性、可观测来设计。本页入门讲清楚云主机、容器服务、Serverless、对象存储与 CDN 分别是什么，并和我们项目里实际用的 Nginx/Docker 自建部署做对比——这块我以了解与评估为主。

1技术点概览

是什么：云原生/公有云部署是把运行环境租给云厂商的一整套方式，核心三类：

  • 云主机（IaaS）：租一台虚拟服务器（阿里云 ECS、AWS EC2），你拿到一台干净虚拟机自己装环境。
  • 容器服务（PaaS）：云厂商托管的 K8s，你只丢镜像、声明要几个副本，集群运维交给云。
  • Serverless（FaaS）：连服务器都不管，你只上传函数/静态包，按调用量计费，没人访问时不花钱。

解决什么问题：自建服务器要自己买机器、托管、出故障修硬件、扩容要等采购；公有云把这些变成"点几下开通、按用量付费、随用随扩"：

  • 收益：免硬件运维、弹性扩缩、按需付费。
  • 配套：静态资源与文件放对象存储（OSS/S3），再套一层 CDN 就近加速——这正是我们前端静态产物常走的路。
  • 本项目定位：我们实际是自建 Nginx/Docker 部署（见对应篇），云原生是我了解与评估过的方向。

2核心概念

图 1 IaaS / PaaS / Serverless 责任边界对比（示意）

2.1 云主机（IaaS，ECS / EC2）

一句话定位：租一台虚拟化的裸机服务器，里面装什么、跑什么你全权负责。

  • 形态：一台带公网 IP 的虚拟机，你 ssh 上去自己装 JDK、Nginx、Docker——和物理服务器用法几乎一样。
  • 与自建关系：相当于"把机房搬进云里"，省去硬件采购与机房托管，但操作系统层还归你管。
  • 要点成本：包年包月固定，适合长期稳定跑的服务。

2.2 容器服务（PaaS，托管 K8s）

一句话定位：K8s 的"主节点与底层运维"由云厂商托管，你只管丢镜像、声明副本数。

  • 你负责：把应用打成镜像、写 Deployment/Service 清单。
  • 云负责：控制面、节点扩容、补丁升级——省去自建 K8s 的运维成本。
  • 关键与本技术栈衔接：和 Docker/Kubernetes 篇一脉相承，只是把"自己搭 K8s"换成"用云托管的"。

2.3 Serverless（FaaS）与静态托管

一句话定位：连服务器都不用管，按实际执行量计费，闲时不花钱。

  • 函数计算（FaaS）：上传一个处理函数，请求来了才拉起容器执行，执行完释放。
  • 前端静态托管：打包好的 dist 直接托管到云静态网站服务（如 OSS 静态网站、Vercel），无需 Nginx。
  • 坑冷启动：长时间没请求后第一次调用要重新拉起容器，有秒级延迟——不适合对延迟极敏感的常驻服务。

2.4 对象存储与 CDN

一句话定位：文件存对象存储，CDN 把内容缓存到全国边缘节点就近分发。

  • 对象存储（OSS/S3/COS）：海量文件（图片、附件、前端静态资源）的高可靠存储，自带 HTTP 访问。
  • CDN：把 OSS 里的资源缓存到离用户最近的边缘节点，全国访问都快，同时挡掉一部分回源流量。
  • 关键前端意义：build 出的带 hash 的静态资源丢 OSS + CDN，比放自己服务器 Nginx 更快、更省带宽。

3工作原理与流程

一句话定位：一个前端静态页面走"OSS + CDN"上云，是最典型的云原生前端发布链路。

图 2 静态资源经 OSS 源站到 CDN 边缘节点的分发（示意）

  1. 本地 build：前端打包出带 hash 的 dist 静态文件。
  2. 上传 OSS：把 dist 整个目录传到对象存储，作为源站。
  3. CDN 回源缓存：CDN 边缘节点首次回 OSS 拉文件并缓存，后续用户请求直接命中边缘节点。
  4. 就近访问：全国用户从离自己最近的边缘节点拿资源，延迟低、不挤源站带宽。

4核心语法与 API 要点

一句话定位：云部署的"语法"主要是控制台点选 + 少量 CLI，和写代码关系不大，重点在概念取舍。

4.1 自建 vs 云原生：选型对比

维度自建（Nginx/Docker）公有云/云原生
初始成本买机器/托管，前期投入大按量付费，起步成本低
运维责任操作系统、故障、扩容全自己管云托管底层，你只管应用
弹性扩容要采购、慢分钟级扩缩
适用内网/数据不出域/长期稳定公网业务、流量波动大

4.2 上传静态产物到对象存储（概念命令）

# 以阿里云 ossutil 为例（概念示意，实际用各家官方 CLI）
ossutil cp -r ./dist/ oss://my-bucket/www/ --update
# 上传后在 CDN 控制台刷新对应缓存，新发布才会对用户生效

要点：带内容 hash 的资源可设长缓存，index.html 必须设不缓存——否则发版后用户拿到旧入口（和自建 Nginx 缓存策略同理，见 Nginx 篇）。

5实战项目经验（自学 + 自建 Demo）

说明：本节是自学 + 概念验证，非企业上云项目。我们真实部署是自建（Nginx 静态托管 + Docker），云原生/公有云我只做过方案评估与本地概念验证，不编造上云履历。

5.1 自学背景与动机

一句话定位：补"自建 vs 上云到底差在哪、OSS/CDN/Serverless 怎么选"的判断框架。

  • 缺口：真实项目是内网自建，没真上云；想把公有云这条路径的概念和取舍亲手过一遍。

5.2 搭建的 Demo 是什么

  • 功能：把一个静态站点用"对象存储 + CDN 缓存策略"的方式验证部署（与自建 Nginx 缓存策略对照）。
  • 范围：概念验证，重点在缓存与刷新策略，不在真买云资源。

5.3 落地步骤（含关键配置）

# 带 hash 的静态资源长缓存；index.html 不缓存（上云与自建通用）
location /assets/ {
  expires 1y;
}
location = /index.html {
  add_header Cache-Control "no-cache";
}

5.4 自学遇到的坑与解决

  • 坑上云忘刷 CDN 缓存：传了新 dist 用户还看旧版——发版流程加刷新 CDN。
  • 坑index.html 被 CDN 长缓存：新入口不生效——index.html 设 no-cache。
  • 坑误估 Serverless 冷启动：常驻低延迟 API 上 FaaS 首次调用秒级延迟——Serverless 只适合波动型。

5.5 成果（可验证能力）

  • 要点能说清 IaaS/PaaS/FaaS 分层、OSS+CDN 缓存策略与刷新时机、Serverless 适用边界；可复现：按上面缓存策略配 Nginx/CDN，验证改 index.html 是否即时生效。

5.6 与真实项目的差异（诚实说明）

真实项目是电力/内网环境，要求数据不出域、现场网络隔离，所以生产仍自建（Nginx+Docker），我没有把系统真正迁上公有云；本节是与自建部署对照的评估/概念验证。

5.7 面试讲法（一句话抓手）

一句话抓手："我们真实部署是内网自建 Nginx+Docker；云原生/公有云我做过方案评估——OSS+CDN 适合静态加速、Serverless 只适合波动型不适合常驻低延迟服务，且必须给 index.html 设 no-cache、发版刷 CDN；诚实说没真把生产迁上云。"

6易错点与面试重点

  • 坑上云后忘刷 CDN：新资源传了但用户命中旧缓存。正解：发版流程里加"刷新 CDN 缓存"一步。
  • 坑index.html 被长缓存：入口文件不更新，整版前端打不开。正解：index.html 设 no-cache，带 hash 资源才长缓存。
  • 坑盲目追 Serverless：把延迟敏感的常驻服务搬上 FaaS，被冷启动坑。正解：Serverless 适合波动型/事件驱动，不适合常驻低延迟服务。
  • 面试高频：IaaS / PaaS / FaaS 怎么区分？答：IaaS（ECS）给你虚拟机、你管系统；PaaS（容器服务）给你运行时、你只管应用；FaaS（Serverless）只给你函数、按调用计费。抽象层级越高、你管的越少、云厂商替你做的越多。
